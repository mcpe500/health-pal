# Gin (Go) Backend Setup Guide

Gin is a high-performance, minimalist web framework for Go, ideal for building APIs and web applications.

## Why Choose Gin?
- **Pros:** High performance, simple API, easy to use
- **Cons:** Limited features out of the box
- **Best for:** High-performance APIs and web services

## Requirements
- Go 1.16 or above

## Installation

1. If you don’t have a `go.mod` file, create it in your `health_pal_backend` directory:
  ```bash
  go mod init health_pal_backend
  ```
2. Download and install necessary Go packages:
  ```bash
  cd health_pal_backend && go get -u github.com/gin-gonic/gin github.com/go-sql-driver/mysql github.com/joho/godotenv google.golang.org/api/oauth2/v2 github.com/dgrijalva/jwt-go/v4 gopkg.in/mail.v2
  ```
  Then run:
  ```bash
  cd health_pal_backend && go mod tidy
  ```

## Core Components

### `main.go`
- Entry point of the application.
- Initializes database connection (MySQL), loads environment variables.
- Sets up Gin router, loads HTML templates.
- Integrates handlers, middleware, and routes.
- Implements graceful server shutdown.
- Serves Swagger UI at `/swagger/*any`.

### `models/user.go`
- Defines the `User` struct and `UserModel` for database interactions (CRUD operations).
- Includes fields for Google authentication, soft deletion, and OTP.

### `handlers/`
- Contains HTTP handler functions for various API endpoints.
- `auth.go`: Handles Google OAuth login, user creation/update, and JWT generation.
- `deletion.go`: Handles account deletion requests (web and API), OTP generation/verification, and email sending.

### `middleware/auth.go`
- Provides Gin middleware for JWT authentication, validating tokens and setting user context.

### `routes/routes.go`
- Centralizes all API route definitions, including public, web, and protected API (`/api/v1`) routes.

### `utils/`
- `email.go`: Utility for sending emails (e.g., OTP emails).
- `google_oauth.go`: Utility for verifying Google ID tokens.
- `jwt.go`: Utility for generating and validating JWTs.
- `otp.go`: Utility for generating and validating OTPs.

### `templates/`
- HTML templates for web-based account deletion forms and results.

## Environment Variables (`health_pal_backend/.env`)
- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`: MySQL database connection details.
- `GOOGLE_CLIENT_ID`: Your Google OAuth client ID for token verification.
- `JWT_SECRET`: Secret key for signing JWTs.
- `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USERNAME`, `EMAIL_PASSWORD`, `EMAIL_FROM`: SMTP server details for sending emails.

## Swagger API Documentation

1.  **Install `swag` CLI tool:**
    ```bash
    go install github.com/swaggo/swag/cmd/swag@latest
    ```
2.  **Generate Swagger docs:** Run the following command in the `health_pal_backend` directory:
    ```bash
    swag init
    ```
    This will generate `docs.go`, `swagger.json`, and `swagger.yaml` in the `health_pal_backend/docs` directory.
3.  **Access Swagger UI:** Once the backend server is running, open your browser and navigate to `http://localhost:8080/swagger/index.html`.
    The API documentation will be available, reflecting the routes defined in `/api/v1`.

## Running the Project

1.  Ensure your MySQL database is running and accessible with the credentials provided in `.env`.
2.  Navigate to the `health_pal_backend` directory.
3.  Run the application:
    ```bash
    go run main.go
    ```
