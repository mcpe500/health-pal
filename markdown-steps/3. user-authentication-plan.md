# Detailed Plan for User Authentication and Account Deletion

## Goal
To implement user authentication using Google accounts only, and provide a secure account deletion mechanism via both the Flutter mobile application and a web-based backend interface.

## Key Requirements
*   **Authentication:** Google OAuth 2.0 based login (only Google Auth).
*   **Backend (Go/Gin):**
    *   Verify Google ID tokens.
    *   Store Google ID, email, name, and profile picture URL.
    *   Manage sessions using JWTs.
    *   Provide API endpoints for Flutter app for account deletion.
    *   Render HTML pages for web-based account deletion.
    *   Send OTPs via an email service for account deletion.
*   **Frontend (Flutter):**
    *   Integrate Google Sign-In.
    *   Communicate with backend for authentication and account deletion.
    *   Implement UI for account deletion with email and OTP.
*   **Account Deletion:** Soft delete users in the database, with email and OTP verification for both Flutter and web interfaces.

### Detailed Plan Steps

#### Phase 1: Backend Setup for Google Authentication and User Management

1.  **Update `health_pal_backend/go.mod`:**
    *   Add necessary dependencies:
        *   `google.golang.org/api/oauth2/v2` (for Google token verification)
        *   `github.com/dgrijalva/jwt-go/v4` (for JWT generation and validation)
        *   `github.com/pquerna/otp` (for OTP generation)
        *   A suitable email sending library (e.g., `gopkg.in/mail.v2` or `github.com/go-gomail/gomail`)
2.  **Database Schema Update (Users Table):**
    *   Modify the `users` table to include:
        *   `id` (PK, UUID or auto-increment)
        *   `google_id` (VARCHAR, unique, from Google token)
        *   `email` (VARCHAR, unique, from Google token)
        *   `name` (VARCHAR, from Google token)
        *   `profile_picture_url` (VARCHAR, from Google token)
        *   `created_at` (TIMESTAMP)
        *   `updated_at` (TIMESTAMP)
        *   `deleted_at` (TIMESTAMP, nullable, for soft delete)
        *   `otp_secret` (VARCHAR, nullable, for account deletion OTP)
        *   `otp_created_at` (TIMESTAMP, nullable, for OTP expiry)
    *   *Decision:* I will create a SQL migration file for this, assuming a basic SQL client is available to run it.
3.  **Implement User Model:**
    *   Create `health_pal_backend/models/user.go` with a `User` struct mapping to the database fields.
    *   Implement CRUD (Create, Read, Update) methods for `User` in the database.
4.  **Google OAuth Configuration & Verification:**
    *   Add `GOOGLE_CLIENT_ID` to `health_pal_backend/.env`.
    *   Create `health_pal_backend/utils/google_oauth.go` with a function to verify Google ID tokens using the `oauth2/v2` library.
5.  **JWT Implementation:**
    *   Add `JWT_SECRET` to `health_pal_backend/.env`.
    *   Create `health_pal_backend/utils/jwt.go` for:
        *   Generating JWTs containing user `id` and `email`.
        *   Validating incoming JWTs.
6.  **Authentication Handlers:**
    *   Create `health_pal_backend/handlers/auth.go`:
        *   `GoogleLoginHandler(c *gin.Context)`:
            *   Receives Google ID token from request body.
            *   Verifies the token.
            *   Extracts Google ID, email, name, profile picture URL.
            *   Checks if user exists in DB; if not, creates a new user.
            *   If user exists, updates their information.
            *   Generates a JWT.
            *   Returns the JWT in the response.
7.  **Gin Middleware for JWT Authentication:**
    *   Create `health_pal_backend/middleware/auth.go` with a middleware function that:
        *   Extracts JWT from `Authorization` header.
        *   Validates the JWT.
        *   Attaches user information to the Gin context for downstream handlers.

#### Phase 2: Account Deletion (Backend)

1.  **OTP Generation and Email Utility:**
    *   Create `health_pal_backend/utils/otp.go` for generating and validating OTPs (e.g., TOTP or random codes with expiry).
    *   Create `health_pal_backend/utils/email.go` for sending emails:
        *   Configure email service credentials in `health_pal_backend/.env` (e.g., `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_USERNAME`, `EMAIL_PASSWORD`).
        *   Function to send OTP emails.
2.  **Account Deletion Handlers:**
    *   Create `health_pal_backend/handlers/deletion.go`:
        *   **Web Interface Handlers:**
            *   `ShowDeleteAccountForm(c *gin.Context)` (GET `/delete-account`): Renders `templates/delete_account.html` (email input form).
            *   `RequestDeleteAccountOTPWeb(c *gin.Context)` (POST `/delete-account`):
                *   Receives email from form.
                *   Generates OTP and stores `otp_secret` and `otp_created_at` for the user in DB.
                *   Sends OTP via email.
                *   Redirects to `/delete-account/verify-otp?email=...`.
            *   `ShowVerifyOTPForm(c *gin.Context)` (GET `/delete-account/verify-otp`): Renders `templates/verify_otp.html` (OTP input form).
            *   `VerifyDeleteAccountOTPWeb(c *gin.Context)` (POST `/delete-account/verify-otp`):
                *   Receives email and OTP from form.
                *   Verifies OTP against stored `otp_secret`.
                *   If valid, updates `deleted_at` timestamp for the user in DB (soft delete).
                *   Renders `templates/deletion_result.html` (success/failure message).
        *   **API Handlers for Flutter:**
            *   `RequestDeleteAccountOTPAPI(c *gin.Context)` (POST `/api/delete-account/request-otp`):
                *   Receives email from request body.
                *   Generates OTP and stores `otp_secret` and `otp_created_at` for the user in DB.
                *   Sends OTP via email.
                *   Returns JSON success/error.
            *   `VerifyDeleteAccountOTPAPI(c *gin.Context)` (POST `/api/delete-account/verify-otp`):
                *   Receives email and OTP from request body.
                *   Verifies OTP.
                *   If valid, updates `deleted_at` timestamp for the user in DB.
                *   Returns JSON success/error.
3.  **HTML Templates:**
    *   Create `health_pal_backend/templates/delete_account.html`, `health_pal_backend/templates/verify_otp.html`, and `health_pal_backend/templates/deletion_result.html`. Gin will render these dynamically.
4.  **Routes:**
    *   Update `health_pal_backend/main.go` to register all new handlers and apply JWT middleware where appropriate.
    *   Example:
        ```go
        // Authentication routes
        router.POST("/auth/google-login", handlers.GoogleLoginHandler)

        // Account Deletion Web Routes
        router.GET("/delete-account", handlers.ShowDeleteAccountForm)
        router.POST("/delete-account", handlers.RequestDeleteAccountOTPWeb)
        router.GET("/delete-account/verify-otp", handlers.ShowVerifyOTPForm)
        router.POST("/delete-account/verify-otp", handlers.VerifyDeleteAccountOTPWeb)

        // Account Deletion API Routes (protected by JWT middleware)
        api := router.Group("/api")
        api.Use(middleware.AuthMiddleware())
        {
            api.POST("/delete-account/request-otp", handlers.RequestDeleteAccountOTPAPI)
            api.POST("/delete-account/verify-otp", handlers.VerifyDeleteAccountOTPAPI)
        }
        ```

#### Phase 3: Frontend (Flutter) Implementation

1.  **Google Sign-In Integration:**
    *   Add `google_sign_in` package to `health_pal_frontend/pubspec.yaml`.
    *   Configure Google Sign-In for Android and iOS platforms as per `google_sign_in` package documentation.
    *   Implement Google login button and logic in Flutter UI to obtain Google ID token.
2.  **API Client & JWT Management:**
    *   Use `http` or `dio` package for making API calls to the Go backend.
    *   Implement a service/repository layer to handle:
        *   Sending Google ID token to `/auth/google-login`.
        *   Receiving and securely storing the JWT (e.g., using `flutter_secure_storage` package).
        *   Attaching the JWT to `Authorization` header for all authenticated requests.
3.  **Account Deletion UI/Logic:**
    *   Implement Flutter UI for account deletion:
        *   A screen/dialog to confirm deletion and initiate OTP request (user's email will likely be pre-filled).
        *   A screen/dialog to enter the received OTP.
    *   Implement logic to:
        *   Call `/api/delete-account/request-otp` to send OTP to user's email.
        *   Call `/api/delete-account/verify-otp` to verify OTP and confirm deletion.
        *   Upon successful deletion, clear stored JWT and navigate user to login/onboarding screen.
