# Detailed Plan for Comprehensive Automated Testing

## Goal
To establish a dedicated, separate Node.js testing project (`health_pal_testing`) for automated End-to-End (E2E) testing of the Health Pal application, covering both the Flutter frontend (compiled APK) and the Go backend APIs. This project will act as a "black box" tester, focusing on external interactions and user flows, ensuring functionalities related to user authentication and account deletion work correctly across the full stack, including positive and negative scenarios, and generating actionable reports.

### Key Requirements
*   **Separate Project:** All tests will reside in a new `health_pal_testing/` directory.
*   **Technology Stack:** Node.js, Jest (testing framework), Axios (HTTP client), WebdriverIO (E2E automation), Appium (mobile automation server).
*   **Best Practices:** Adherence to best practices in test code organization, naming, and implementation.
*   **Full Stack Coverage:** Test interactions between Flutter frontend (compiled app) and Go backend APIs.
*   **App UI Testing:** Automated testing of the actual Flutter application UI (mobile version via APK).
*   **API Endpoint Testing:** Direct testing of Go backend API endpoints.
*   **Positive & Negative Tests:** Comprehensive test cases for all relevant scenarios.
*   **Reporting:** Generate reports (e.g., JUnit XML).

### Detailed Plan Steps

#### Phase 1: `health_pal_testing` Project Setup

1.  **Create Project Folder:**
    *   `mkdir health_pal_testing && cd health_pal_testing`
2.  **Initialize Node.js Project:**
    *   `npm init -y`
3.  **Install Core Libraries:**
    *   For API testing: `npm install jest axios`
    *   For Flutter APK testing: `npm install -D @wdio/cli`
4.  **Configure WebdriverIO (`npx wdio config`):**
    *   This is an interactive setup. Make the following key choices:
        *   **What type of testing would you like to do?** `E2E Testing - of Web or Mobile Applications`
        *   **Which framework do you want to use?** `Jest`
        *   **Where is your app located?** Provide the path to your Flutter `.apk` file (e.g., `../health_pal_frontend/build/app/outputs/flutter-apk/app-release.apk` - *Note: You will need to build the Flutter APK first*).
        *   When asked to install services, include `appium`.
    *   This will generate `wdio.conf.js` and update `package.json`.
5.  **Install Appium:**
    *   **Manual Step:** Ensure Appium is installed globally (`npm install -g appium`) and the Appium server is running before executing APK tests (`appium`).
    *   **Manual Step:** Ensure you have Android SDK tools and a running emulator/device.

#### Phase 2: Backend API Testing (using Jest and Axios)

**Directory Structure:**
*   `health_pal_testing/api_tests/`
    *   `auth.test.js`
    *   `deletion.test.js`
    *   `config.js` (for API base URL and test-specific data)

**Test Cases:**

*   **`auth.test.js`:**
    *   **Positive:**
        *   `testGoogleLogin_NewUserSuccess`: Send a valid Google ID token (mocked), verify user creation in DB (via API call or direct DB check), receive valid JWT.
        *   `testGoogleLogin_ExistingUserSuccess`: Send valid Google ID token for existing user, verify user update, receive valid JWT.
        *   `testProtectedEndpoint_Success`: Use a valid JWT to access `/api/v1/profile`, verify 200 OK and expected data.
    *   **Negative:**
        *   `testGoogleLogin_InvalidIDToken`: Send an invalid Google ID token, verify 401 Unauthorized.
        *   `testProtectedEndpoint_Unauthorized`: Attempt to access `/api/v1/profile` without JWT, verify 401.
        *   `testProtectedEndpoint_ExpiredToken`: Use an expired JWT, verify 401.
*   **`deletion.test.js`:**
    *   **Positive:**
        *   `testRequestOTPApi_Success`: Request OTP for a valid user, verify 200 OK. (Requires mocking email sending or using a test email service).
        *   `testVerifyOTPApi_Success`: Provide correct OTP for a user, verify 200 OK and user soft-deleted in DB.
    *   **Negative:**
        *   `testRequestOTPApi_UserNotFound`: Non-existent email, verify 404.
        *   `testVerifyOTPApi_InvalidOTP`: Invalid OTP, verify 401.
        *   `testVerifyOTPApi_ExpiredOTP`: Expired OTP, verify 401.
        *   `testVerifyOTPApi_NoOTPRequested`: Attempt to verify OTP without requesting one, verify 400.

**Implementation Steps:**

1.  **Create `api_tests/config.js`:** Define `API_BASE_URL` and any test credentials.
2.  **Write Test Files:** Implement test cases using Jest's `describe` and `test` functions, and Axios for HTTP requests.
3.  **Mocking/Test Setup:** For tests involving Google ID tokens or email sending, consider:
    *   Using dummy/pre-generated Google ID tokens for testing (ensure they are valid for your `GOOGLE_CLIENT_ID`).
    *   Setting up a test email server (e.g., MailHog) or mocking the `SendOTPEmail` function in the Go backend for testing purposes.
    *   Ensuring the Go backend is running and configured to use a *test database* that can be cleaned before each test run.

#### Phase 3: Flutter APK E2E Testing (using WebdriverIO and Appium)

**Directory Structure:**
*   `health_pal_testing/flutter_apk_tests/`
    *   `auth_e2e.test.js`
    *   `deletion_e2e.test.js`

**Test Cases:**

*   **`flutter_apk_tests/auth_e2e.test.js`:**
    *   `testGoogleLoginFlow`:
        *   Launch app.
        *   Find and tap Google Sign-In button.
        *   (Crucial: Automate interaction with Google sign-in pop-up, possibly via Appium's native context or pre-configured test accounts).
        *   Verify navigation to Home Screen (e.g., check for a welcome text).
    *   `testProtectedDataAccess`:
        *   (Assume logged in state, or perform login as part of setup).
        *   Find and tap "Fetch Protected Data" button.
        *   Verify the protected data is displayed correctly.
*   **`flutter_apk_tests/deletion_e2e.test.js`:**
    *   `testAccountDeletionFlow`:
        *   (Assume logged in state, or perform login as part of setup).
        *   Find and tap "Request Account Deletion OTP" button.
        *   (Automate OTP retrieval, e.g., from a test email service or log output).
        *   Enter OTP in the dialog.
        *   Tap "Verify & Delete Account" button.
        *   Verify account deleted message and navigation back to Login Screen.

**Implementation Steps:**

1.  **Build Flutter APK:** Before running these tests, build the Flutter app for the target platform (e.g., `cd health_pal_frontend && flutter build apk --release`).
2.  **Update `wdio.conf.js`:** Ensure the `appium` service is enabled and the `capabilities` section correctly points to your Flutter APK.
3.  **Write E2E Test Files:** Implement test cases using WebdriverIO's API (e.g., `$('~elementLabel').click()`, `expect(element).toHaveText()`).
4.  **Accessibility Labels:** Ensure your Flutter UI widgets have appropriate `Semantics` labels for WebdriverIO to target elements reliably.

#### Phase 4: Reporting and Automation

1.  **Test Reports:**
    *   Jest will generate its own test results. WebdriverIO can also generate various reporters (JUnit, Allure, etc.) configured in `wdio.conf.js`.
    *   For unified reporting, configure Jest and WebdriverIO to output JUnit XML.
    *   Create a `test_reports/` directory at the root (`health-pal/test_reports`).
2.  **Root `Makefile` (health-pal/Makefile - *new*):**
    *   Add a `test-all-e2e` target that orchestrates:
            1.  Ensuring Go backend is running.
            2.  Running Flutter E2E tests from `health_pal_testing`.
            3.  Generating test reports.
        *   Example command: `cd health_pal_testing && npm test api_tests -- --reporters=jest-junit`
        *   Example command: `cd health_pal_testing && npx wdio run wdio.conf.js -- --reporters=junit`
        *   Add a `test-reports` directory at the root (`health-pal/test_reports`).

### Prerequisites (Manual Installation by User)
*   Node.js and npm/yarn.
*   Appium Server (`npm install -g appium`).
*   Android SDK and a configured emulator/physical device (for mobile E2E).
*   Flutter development environment (to build the APK).

This plan provides a robust and separate testing suite, adhering to best practices.
